## Reading this matrix

- **14 engines carry `tested` state with live adapters** (`src/engines/registry.json` — 45 records): cadquery (STEP quantities, tessellation, parametric rebuild), IfcOpenShell (IFC quantities, tessellation), gmsh (FE meshing), pandapower (power flow), SimPy (DES), LibreOffice (document conversion), pdfplumber / ezdxf / tesseract (vector PDF takeoff, DXF takeoff, sheet OCR), scikit-fem (plane-stress FEA), pyswmm (SWMM), SfePy (CFD transport), amaranth + yowasp-yosys (RTL synthesis). The lane opened 2026-10-21 (W2-b) with model-derived quantities from STEP (cadquery) and from IFC (IfcOpenShell) — the first REAL engine adapters. Evidence: fixtures + analytic cross-checks + test names in [engine-inventory.md § First real engine adapters](engine-inventory.md#first-real-engine-adapters-w2-b-2026-10-21).
- **Every adapter lane is benchmark-validated by the harness** (`src/engines/validation/`, corpus [`tests/validation/corpus-manifest.json`](../../tests/validation/corpus-manifest.json) — grown from the 11-case W2-c start to a **42-case corpus**: STEP/IFC quantities, tessellation, FE meshing, FEA, CFD transport, DES, power flow, SWMM, CPM, RTL, vector takeoff, OCR, DXF, parametric rebuild, document conversion) which drives the real production bridges against hand-derived closed-form ground truth with set-equality, bitwise-determinism and honest-error enforcement; latest run **42 pass / 0 fail / 0 skip** (`bun run validate:engines`, evidence: [validation-report.md](validation-report.md) + [`tests/validation/report.json`](../../tests/validation/report.json)). The status vocabulary defines no `validated` state, so the capabilities remain `tested` with the harness evidence recorded here and in the registry's per-engine `validation` fields (state-vocabulary changes are the TL's call).
- **Model tessellation for the 3D viewer is `tested` (harness-validated)**: the eos-mesh/1 tessellation bridge (`src/engines/adapters/mesh.ts` → `step_mesh.py` / `ifc_mesh.py`, W2-d) turns STEP/IFC into byte-deterministic viewer meshes; the harness corpus pins element refs set-equal to the quantity ledger, per-element vertex/triangle counts, byte-determinism and divergence-theorem volumes vs closed forms (planar exact, curved ≤ 1% pinned with observed errors recorded) — the mesh cases now ride in the 42-case corpus above. See the [tessellation section in engine-inventory.md](engine-inventory.md#tessellation-adapters--the-eos-mesh1-bridge-w2-d-2026-10-21) and [validation-report.md](validation-report.md).
- **Everything else below is `planned`:** those engines are audited upstream (registry: 45 records — 30 `planned` at audit close + pdf2takeoff added 2026-10-30 per ADR-0009) but no integrated adapter exists yet (adapters land per ADR-0005 as evidence accrues); 14 engines are installed on the dev host (uv venv + PATH tesseract/LibreOffice). Detection probes for the rest are specified and tested; adapter capabilities get their own states as evidence accrues. FreeCAD/Bonsai were investigated in this sandbox on 2026-10-21 (not importable, no binaries, no pip-installable distribution) — both stay `planned` for editor/authoring; this slice's geometry is served by cadquery/IfcOpenShell.
- **Platform capabilities (implemented now)** are listed at the end — these are the TL-provided foundation the engines plug into, with their real states.
