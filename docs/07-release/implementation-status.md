## Known limitations (current, honest)

1. Single-operator local mode; no auth.
2. Dev database is SQLite; PostgreSQL migration defined but **not verified end-to-end**.
3. Native editor/authoring adapters (FreeCAD, LibreCAD, DWG round-trips) are not implemented — investigation note in engine-inventory.md records why (not installable in this sandbox; no pip-installable FreeCAD/Blender). Geometry for the viewer and quantity derivation is served by cadquery + IfcOpenShell (installed in the venv, harness-validated). The Engines workspace shows registry + real detection results only (3 of 35 installed at last probe: LibreOffice, cadquery, ifcopenshell).
4. Workflow runtime executes single-file (in-process sequential executor, one run at a time — single-operator dev reality; no scheduler/cron/multi-instance claims). Recovery marks interrupted `running` rows failed honestly; resuming is the explicit `retry` action. The "agent" is a named deterministic orchestration actor — no LLM planning is involved anywhere (ADR-0006 §2 untouched).
5. Drawing-measured quantities are entered from calibrated-sheet readings; calibrated PDF/vector measurement tools, symbol counting and cutouts are **not implemented yet** — no Bluebeam/PlanSwift parity is claimed. The quantity-derivation validation harness shipped (AC-P3-09); a broader measured-vs-model reference harness can extend it later.
6. IfcOpenShell on this host lacks the OCC geometry backend (PyPI wheel): BaseQuantities are exact; geometry fallback is mesh-based — exact for planar solids (observed rel ~1.9e-16), approximate for curved surfaces (observed rel 3.2e-3 volume / 9.6e-4 area on the Ø400×3000 corpus column, inside the pinned 1%) — recorded per-row in `raw.method` and per-comparison in the harness reports. A future wheel-default deflection change beyond 1% fails the harness loudly rather than passing silently.
7. Estimate lines freeze once approved/superseded. Superseding (draft/in_review/approved → superseded) is terminal and keeps the estimate for audit with its approval payload; superseded estimates are not exportable. Recompute is now real at the artifact level (Phase 4): stale workflow outputs are re-derived by an explicit retry/re-queue, and staleness cascades ride Journey-G — but there is still no one-click "recompute estimate from a new takeoff" flow (Phase-5 controls work).
8. Upload writes bytes before the DB transaction; a failed registration can leave orphaned bytes (logged loudly). **The cleanup tooling has shipped (Phase 4)**: `POST /api/admin/storage/scan` lists true orphans and `DELETE /api/admin/storage/orphans {confirm:true}` removes exactly the fresh server-side scan — verified by AC-P4-07 with both-ways DB↔store consistency. A scheduled automatic sweep remains Phase-6 work.
9. Rate resolution prefers effectiveFrom ≤ now, else falls back to the newest rate row — chosen rate ids are always recorded in the line breakdown, but nothing warns about future-dated rates yet.
10. Browser automation of file-picker inputs hit a tool-level (agent-browser/CDP) issue during verification; upload paths verified byte-exact via the real API instead (acceptance catalogue notes).
11. The validation harness covers the quantity-derivation + mesh-tessellation corpus (11 cases, cadquery + IfcOpenShell, incl. 9 mesh blocks); the other 33 registry engines remain `planned` with no harness cases. Harness reports carry `ranAt` — regenerate with `bun run validate:engines`.
12. The 3D viewer is a read-only preview (no measurement/editing); element picks are cross-referenceable with ledger rows by identical elementRef strings, but there is no UI cross-navigation yet (Phase-2b candidate). STEP meshes carry OCCT per-face duplicated vertices (not welded) — visually irrelevant, documented. Viewer selection resets to the first model on tab remount (same behavior as other tabs).
13. useApi is manual-refresh: mutations refresh their OWN workspace's lists, but cross-workspace caches wait for their next trigger. The Phase-4 lane fixed its own face of this (AgentsWorkspace.onMutated nudges the project-level caches on workflow completions/approvals — browser-verified); Studio/Takeoff derive actions still leave the Artifacts tab waiting for its next explicit refresh (pre-existing pattern, Phase-2b candidate).
14. Same input set + different title → build_report APPENDS a revision to the same report artifact (find-or-create matches by the derived_from target set, mirroring the mesh route); two runs on the same source therefore share one report artifact. Changing titles between runs does not fork the artifact.
